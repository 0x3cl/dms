# DocTrack agent guide

Laravel 12 / PHP 8.3+ with Inertia 2, **Vue 3 inline-template `.js` pages**, Tailwind 4, Pest, and Pint. Follow the code immediately adjacent to the change; do not scan `CLAUDE.md` or unrelated modules for ordinary focused work.

## Load context by impact

1. Start with the requested file, its direct caller/route, the sibling implementation, and the closest test.
2. Expand one hop only when the change affects a contract: route/controller/page; model/migration/relationship; or a shared component and its consumers.
3. Read `CLAUDE.md` only for cross-module work, a new flow, or an unresolved design question. Search exact symbols with `rg`; do not bulk-read source trees.
4. For the design system — tokens, component APIs, page recipes — read `documentation/design-system.md` before writing any page or component.

## Working rules

- Use `php artisan make:* --no-interaction` for generated artifacts. Do not add dependencies or new top-level directories without approval.
- Run `vendor/bin/pint` after PHP edits, and `npm run build` (or `npm run dev`) after frontend edits — a Vue inline template only fails at build time.
- Add focused regression coverage for behaviour changes and run the narrowest relevant test: `php artisan test --compact --filter=testName`.
- Keep routes, controllers, models, Inertia props and page prop names aligned. Use named routes where the surrounding code does.

## Non-obvious invariants

- **Vue components are plain `.js` files, not `.vue` SFCs.** Every file in `resources/js/pages` and `resources/js/components` is `defineComponent({ template: \`...\` })`. `vite.config.js` aliases `vue` to the runtime **+ compiler** build specifically to compile those inline template strings; do not "fix" that alias or introduce an SFC without checking first, because page resolution in `app.js` globs `./pages/**/*.js`.
- **Card, panel, drawer and modal titles are `uppercase tracking-wide`.** The only exception is the page-title `<h1>` in `AdminShell`'s sticky header and the landing hero.
- **`border-rose-500` on an invalid input is load-bearing.** The global `router.on('error')` hook in `app.js` scrolls to and focuses the first element carrying it. Rename it and validation stops taking the user to the problem.
- **Dark mode is a variable remap under `html.dark`, never a `dark:` variant.** `resources/css/app.css` rewrites Tailwind's `--color-*` custom properties, so a utility keeps its intent and only its value changes. Do not add `dark:` classes — they would be the only ones in the codebase and would fight the remap. `--color-white` is deliberately *not* remapped (it is both a card surface and a button label), so `.bg-white` is patched per-utility instead.
- **A page's own `<main>` must carry `flex-1`.** `app.js` wraps every page in `flex min-h-screen flex-col` between the navbar and footer. Inertia pages render `<Head>` and `<main>` as sibling roots, so Vue cannot fall a class through onto a fragment, and a short page without it leaves a white gap above the footer. `AdminShell` already does this; standalone pages (`index.js`, `auth/*`) must do it themselves.
- **A document has no lifecycle.** The End Action is gone — route, controller method, `App\Enums\DocumentStatus`, `DocumentAction::Ended`, `StatusBadge` and the `documents.status` / `ended_at` columns. An uploader who wants a document out of circulation deletes it (soft, so the trail survives). Do not reinstate a status column "for later": a lifecycle state nothing writes is what produced the permanently-zero dashboard count.
- **"My Documents" and "All Documents" are one page of tabs** — All, Uploaded by me, Shared with me, and **Deleted** when the viewer has withdrawn something — and the All tab's grant (`documents-all.read`) is resolved **in the controller**, not by middleware: a tab is a filter on one screen, so an unreachable one degrades to "Uploaded by me" rather than refusing the page. `/documents/all` is a redirect. The upload screen is `/documents/upload`, still named `documents.create`.
- **Deleting a document is a soft delete and is reversible.** The Deleted tab is `Document::onlyTrashed()->uploadedBy($user)` and `POST /documents/{document}/restore` (`withTrashed()` on the binding, or every subject 404s; gated on `documents.delete` plus `owns()`). It touches no file: a tracked document's bytes stay in My Files, and `files:purge` keeps them while a trashed document points at them.
- **Shared with Me is a filter on My Files, not a screen.** At the top of a person's own storage, items shared *with them* are listed beside their own, queried from `item_shares` directly — not through `scopeVisible()`, which would also admit every public item and the administrator's reach. Each row's `access` badge comes from the **grant's `AccessSource`**, never from comparing `user_id`.
- **Sharing from the drawer is link-based only.** People are named where the thing is created (the New folder dialog, the document upload form). `ShareController::store()` and the directory the share-state endpoint used to ship are gone; revoking stays.
- **A *permanent* delete carries a four-digit code the server issued; moving to trash does not.** `App\Services\Files\DeletionConfirmation` holds it in the session, spends it on use, and `files.purge` refuses a mismatch. Never move that check into the browser — a code the page invents and verifies is a label on a button. The code used to guard both, which put identical friction on a reversible act and an irreversible one; friction applied to everything stops being read, and people learned to type the digits to get past the dialog — the habit the code exists to interrupt. `PURPOSE_PURGE` is still a validated parameter with one value, because the purpose is what binds a code to its act; `/files/confirm-code` refuses to mint one for anything else, since a code nothing checks is a credential handed out for nothing.
- **A restore puts an item back under the chain above it**, reviving trashed ancestors (with `withTrashed()`, because the soft-delete scope hides exactly the folders that need reviving), reattaching to the owner's root when that chain cannot be rebuilt, and **renaming rather than refusing** on a collision — a restore has no second chance to ask.
- **The `files` row *is* the file's current version**, and `storage_path` is the one statement of where its bytes are. Only superseded versions live in `file_versions`. That is what keeps `unique(folder_id, name)`, `scopeVisible()`, `documents.file_id` and every `public_id` URL untouched by a replacement — so a tracking code, a printed label and a share link all survive one.
- **A replacement is a verbatim move**: the current-version descriptor goes from `files` into `file_versions` unchanged, then the new descriptor is written onto `files`. `FileVersionService` does that; `FileManager::{replace,revertTo}()` own the ability check, the lock, the transaction and the audit row. A **revert copies forward** as a new version — never move the pointer back.
- **A version adds no reach.** `AccessResolver` never takes a version: one rule, resolved against the `File` (or its `Document`), and a version has no visibility, shares or links of its own. Read bytes through `App\Contracts\StoredBytes`, which is deliberately never an authorization subject. `FileVersionTest` asserts this differentially.
- **A share link reaches the current version only** — `?version=N` is a 404 on `share.stream`. Anything else would widen every token already in circulation.
- **Only a tracked document's uploader may replace its file.** `FileManager::mayReplace()` is the one source for the refusal *and* the `can.replace` payload, because `FileAbility::Rename` is reachable through a `ShareAbility::Manage` share and the bytes a printed code names must not be swappable by a share holder. There is deliberately no `FileAbility::Replace`.
- **`FileStorage::delete()` unlinks every version's bytes.** `file_versions.file_id` cascades, so a purge drops the rows by itself — without this their bytes stay on disk, referenced by nothing that could ever find them.
- **`FilePathFactory::forVersion()` is the only path builder, and version 1 has no segment** — so every pre-versioning path still resolves and nothing needed rewriting. Derive on write; **read the path from the column**, because a version's extension may differ from the file's current one.
- **`recordOnce()`'s debounce key includes the version.** Previewing v1 then v2 inside the window are two different things being opened.
- **`DocumentLog::record()` derives `version` from `$document->file?->version`** when it is not passed, which is what keeps every existing caller correct. Only the path serving a *superseded* version passes it explicitly. Null is meaningful, never backfilled.
- **A tracked document's replacement is written to `document_logs` directly** by `FileManager::replace()` as `DocumentAction::FileReplaced` — **not** through `FileEventRecorder::DOCUMENT_EQUIVALENTS`, which stays at two entries. A revert gets no document action of its own.
- **A restore also revives everything the same delete took, matched on `deleted_batch`.** Every delete stamps one uuid across `files.deleted_batch` and `folders.deleted_batch` for every row it touches, and `FileManager::restoreSubtreeOf()` revives exactly the rows carrying that stamp — so a folder does not come back empty, and a child trashed separately *earlier* stays in the trash. Never infer the grouping from `deleted_at`: it is second-precision, so two unrelated deletes in one second are indistinguishable. A null batch (a row trashed before the column existed) restores as item-and-ancestors only.
- **A trail row snapshots the actor's face as well as their name.** `document_logs.actor_avatar_seed` and `actor_profile_image` are copied onto the row for `resources/js/avatar.js`; do **not** eager-load `User` to decorate a trail, or the history changes when somebody edits their profile and renders nothing once the account is erased. Null is normal — `avatar.js` derives a face from `actor_name` alone.
- **Every name check uses `withTrashed()`.** `(folder_id, name)` and `(parent_id, name)` are unique over soft-deleted rows too, so a name held by something in the trash is still taken; leaving them out turned an ordinary re-upload into a 500.
- **A structural operation records its own failure.** `FileManager::attempt()` wraps the transaction behind move, copy, delete, restore and purge, writes an `outcome: 'failed'` row **after** the rollback — inside, it would be rolled back with the work it was recording — and re-throws untouched. Authorization refusals are deliberately outside it.
- **The page never chooses a preview viewer.** `App\Services\Files\FilePreview` resolves it behind the `view` ability and returns one of three answers: `renders_locally` (a PDF, drawn by the browser), `client_renderer` (`docx`/`xlsx`, drawn by `OfficeRenderer` from our own stream), or `viewer_url` (a **signed, expiring** URL to `files.viewer` for **Microsoft's Office viewer** to fetch — the one door the private disk opens without a session).
- **Word and Excel no longer leave the building.** `FilePreview::CLIENT_RENDERERS` sends `docx`/`docm`/`xlsx`/`xlsm`/`xlsb`/`csv` to `docx-preview` and SheetJS in the browser, so no URL is minted for them, they render on localhost and on an office LAN (where the Office viewer renders *nothing*), and **a confidential item is previewable for the first time** — there is no outside URL left to refuse. Only PowerPoint and the legacy OLE2 `.doc`/`.xls` still use the viewer, and for those the old rules stand: never for a confidential item, and the visibility is re-checked on every fetch, because an item can be reclassified after a URL is handed out.
- **`OfficeRenderer` never inserts a spreadsheet as markup.** Cells are read as *data* (`sheet_to_json`) and drawn by Vue's text interpolation, so escaping is a property of the mechanism rather than a pass over the output. It used to take SheetJS's generated table, parse it inert, strip every script/style/handler attribute and insert it with `innerHTML` — a defence that had to be correct to be safe, and the single most expensive step in the render. Same reason SVG is kept out of the image path.
- **`OfficeRenderer` bounds its work, and a big file is a decision rather than a freeze.** The render happens on the reader's machine, so its cost is theirs: a workbook is drawn **one sheet and one 300-row window at a time** (the cost is in the node count, and `table-layout: auto` measures every cell before it places a column), past 25 MB (Word) / 12 MB (Excel) the gate states the size and offers Download or "Preview anyway", the transfer reports a real percentage off `content-length`, the thread is yielded before each heavy step so that percentage can paint, and nothing large is reactive — a `shallowRef` for the rows and a plain variable for the workbook, because deep reactivity over a parsed workbook is a second full pass over every cell. `docx-preview`'s `experimental` (tab-stop computation, which measures laid-out text per tab) is off above 4 MB. It also loads both libraries dynamically (they are large, and most previews are a PDF) and tickets each render — the ticket is checked inside the download loop too, so moving on cancels the transfer rather than finishing it into a host nobody is looking at.
- **Off-screen Word pages are not laid out.** `.office-render .docx` (one page) carries `content-visibility: auto` with `contain-intrinsic-size: auto 1056px`. Without it the browser styles and paints every page of a long report on every scroll frame, which is lag that outlives the render; the intrinsic size is what keeps the scrollbar from jumping as pages enter and leave.
- **An embedded viewer fetches from *our* server, not from the browser.** `FilePreview::viewerCanReachUs()` reads `app.url` and mints nothing when it is `localhost`, a `.test` domain or a private range — a frame pointing at an unreachable host stays empty forever, and an honest "download to view" beats a spinner. This is why document previews never work on a developer machine.
- **An account with no photo and no seed still has a face.** `resources/js/avatar.js` generates one from the person's name; `users.avatar_seed` is a deliberate pick. A photo and a seed are **exclusive** — setting either clears the other, and the uploaded bytes go with it.
- **Access is role-based, and the two halves are one mechanism.** Permissions are `{module}.{action}`; the whole vocabulary is `App\Support\Modules` and the two built-in roles are `App\Support\Roles`. `files.manage` gates Browse Storage as well as the administrator's read — `files-browse.read`, `files-shared.read` and `files.write` have been **retired**, because a permission that gates nothing is a checkbox granting nothing. A module's routes carry `permission:` middleware in `routes/web.php`, and `AdminShell`'s `MODULES` entries each name the permission that reaches them. **Add an entry and you add its route gate in the same change** — a hidden sidebar entry over an open route reads as protection that is not there. `SUPERADMIN` is short-circuited by the `Gate::before` hook in `AppServiceProvider`, so it is never enumerated. See `documentation/architecture.md` → Access model.
- **The upload policy is one row.** Not one per module: `scope` is the single row's unique key and nothing branches on it. `UploadPolicy`'s methods take no scope — the document register, the file manager and archive entries all read the one policy, so tightening it reaches every upload path.
- **The upload policy is one list.** `upload_settings.allowed_types` — an entry per permitted extension with its own size window — and not in the list means refused. The MIME types an extension may sniff as, and the refusal of program formats, are **derived in `App\Support\FileTypes`** rather than configured; three lists that had to agree is what refused a genuine `.xlsx` with "is not the kind of file it claims to be". Only a *positive* contradiction between name and contents is a refusal: `application/zip` for a `.docx` is correct (OOXML *is* a zip), and `application/octet-stream` is `finfo` concluding nothing. The coarse Laravel `max:` rule must stay the **widest** per-type window, since it runs before the extension is known.
- **An upload form states the policy, never a literal.** `accept` comes from `UploadPolicy::limits()` on both upload surfaces, with `UploadLimitsHint` under the field. A hard-coded `accept=".pdf,.doc,.docx"` outlived the rules it was copied from and hid every permitted spreadsheet from the browser's own dialog.
- **A document has three access levels and they answer two questions.** `public` reads to anyone with the code; `private` and `confidential` read **identically** — the uploader and the tagged people — and differ only in whether a link may exist. So `AccessResolver::forDocument()` keeps three clauses (confidential joins the recipient clause) and the link path asks `linkableNow()`; the public clause asks `restrictedToNamedPeople()`, never `=== Public`. A document's share link is minted against the **document**, never its `File` row, or it would answer to the file's visibility instead. Re-checked on every redemption, because a document can be reclassified after a link is sent.
- **The document type is a tag.** It picks the tracking-code prefix and gates nothing — a document of type "Confidential" is not classified confidential.
- **A module permission is not a per-record permission.** `documents.delete` says the capability exists for this user; `DocumentController::owns()` still decides which document it applies to. Withholding the module permission would not protect anyone else's upload — it would stop a user withdrawing their own.
- **Sign-in takes `employee_id` or `email`, in one field.** The form posts `login`; `LoginRequest::credentials()` picks the column from the shape of the string (a valid email address is an email, everything else an employee ID) and makes exactly one `Auth::attempt()`. `users.email` is nullable and unique — an account without one is unreachable by email and cannot self-serve a reset. Authentication goes through `LoginRequest`, which is where the rate limiting lives — never inline `Auth::attempt()` in the controller again.
- **There is no email verification.** `users` has no `email_verified_at` column and `User` does not implement `MustVerifyEmail`. Reinstating it means adding both first; `routes/auth.php` says so too.
- **Tutorials are frontend-only** — no route, no table, no permission of their own. A tour declares the `permission` of the feature it teaches and the menu filters on `auth.permissions`. A step's element is pointed at by a `data-tour` attribute, and **an anchor a tour references but no markup defines is a silent break**: the step is dropped or falls back and nothing fails. Scan the tour files for `[data-tour="…"]` and diff against the markup after adding a step.
- **Soft delete protects the *link*; hard delete protects the *history*.** `users`, `divisions`, `sections` and `documents` are soft-deleted, so a closed account cannot sign in while everything it owns still knows who owns it. Audit rows keep `nullOnDelete` beside a name snapshot, because the trail must survive a permanent erasure too. **In a test, `delete()` is the soft one** — if you mean "the row is gone for good", write `forceDelete()`.
- **An account that owns anything cannot be closed without an ownership transfer.** `OwnershipTransferService` moves folders, files and documents and deliberately does *not* touch the audit trail or `documents.uploader_name` — ownership is a fact about now, an audit row a fact about then. It never moves a root folder: two roots breaks the uniqueness the tree depends on, and MySQL would not catch it.
- **Upload limits are a row, not a literal.** Every upload path goes through `App\Services\Files\UploadPolicy`, which reads the one administrator-editable `upload_settings` row. Extension **and** sniffed contents are both checked. The limits sent to the browser are a courtesy; the server is the gate.
- **An archive never chooses a path.** `ZipArchive::extractTo()` is never called — every entry is streamed out and written to a path built by `FilePathFactory` from a fresh `public_id`, which is what makes zip-slip impossible rather than filtered against. Validate the whole archive *before* opening the transaction, and collect every written path so a rollback can unlink them: disk writes are not transactional. See `documentation/modules/upload-settings.md` for the bomb, symlink, nesting and encryption guards.
- **Every file-manager operation goes through `App\Services\Files\FileManager`**, which resolves the ability on the subject *and the destination*, transacts, and writes the audit row. The controllers validate shape and hand over — none of them decides access. Checking only the subject lets a share on one folder deposit files into another the user cannot write.
- **`ToastStack` is mounted in `app.js`, outside the Inertia page**, beside the navbar and footer — a toast is usually raised by an action that then navigates, so a stack inside the page component would be unmounted by the very visit carrying the message. Its store is module-level, so anything may `pushToast()` without a prop chain; that is for the outcomes that never reach a flash at all, such as a clipboard copy or a refused revoke answered with a 422. It watches the `flash` **object**, not the message string: every Inertia response builds fresh props, so saving the same form twice raises two toasts, where watching the string left the second one silent.
- **A dual-view list keeps `view` in the query string** and renders one paginator through both bodies. That is what makes "switching views preserves page, filters, sort and search" true by construction rather than by a behaviour that drifts.
- **An index table's Actions column is `RowActions`, and it is icon-only.** Label text moved to `title` (hover) and `aria-label` (assistive tech), never dropped — the column is the part of a row people click, and spelling out "Edit"/"Delete"/"Open" is what forced every table to a `min-w-[…]` and pushed that column off the right edge. Pass actions as data; do not hand-roll a button row.
- **Row-level actions come from a server-resolved `can` object** on each payload, never from reading `auth.permissions` in a template — otherwise a read-only share shows a Delete button.
- **The one exception to `scopeVisible()` is "what was *given* to me".** The shared entry points at the top of My Files are queried from `item_shares` directly, because `scopeVisible()` also admits public items and the administrator's reach, which nobody gave anyone. Every other listing goes through the scope.
- **Every listing of files or folders must go through `AccessResolver::scopeVisible()`.** It is the same rule as `grant()` expressed in SQL. Fetching broadly and filtering in PHP afterwards is a leak: the paginator totals are wrong and those totals disclose existence even when the row is never rendered. `FileListingTest` holds a differential test that resolves every row through `grant()` and asserts the listing returns exactly that set — it has caught two real bugs already.
- **`files.storage_path`, never `files.path`.** `folders.path` is the materialized *ancestor* path; a file's ancestor path is its folder's path plus that folder's own id. When both columns were called `path` the SQL searched a file's **disk** path for a folder id, which never matches — so every ancestor rule silently evaluated as "no ancestors", listing a private folder's public file to everyone. `AccessResolver::ancestorPathSql()` is the one place that distinction lives.
- **Inheritance, in one sentence each:** effective visibility is the **most restrictive** value on an item and every folder above it, excluding the account's root (a container, never rendered, created private — leaving it in clamps everything to private); shares travel **downward** and the **nearest** ancestor carrying one wins; a share on the item itself beats anything inherited; **confidential** is reachable only by a share naming the item, never inherited and never via a link. See `documentation/modules/sharing.md`.
- **A QR Tracker encodes the document's share link**, not its tracking URL, and `SharingService::ensureLinkFor()` mints one at upload so the label has a real target. A confidential document has none and falls back to the tracking URL. **Whether that label is a bearer credential is the link's `ability`**, not the document's level: a restricted document's link is minted on `ShareAbility::Restricted`, which resolves to the holder's own access, and only a deliberate widening to view or download makes the URL a key. `downloadQr()` is restricted to whoever may share the document, and the page ships the link's symbol only to the uploader. The stored PNG is rewritten on create, regenerate and revoke, never on edit — an edit keeps the URL.
- **`FilePreviewPane` is the one preview renderer.** The document page renders the file inline (there is no "View file" button) and `FilePreviewModal` delegates to the same component. The descriptor is still fetched rather than shipped as a prop, because for PowerPoint and legacy Office it mints a short-lived signed URL.
- **A trail's filters are one builder, one parser, one dialog, one tab bar.** `DocumentLog::scopeTrail()`, `DocumentLogController::filters()`, `TrailFilters` and `TrailVersionTabs` serve both the document panel and the full-history page. The file version is the tab bar rather than a select in the dialog — same `version` parameter, counted per tab by `DocumentLog::versionTabsFor()` under every filter but the version itself, and absent entirely until a file has been replaced. Every filter reads a **snapshot column** — the office filter narrows by where the actor sat *then*, and the offices offered are derived from the rows so the filter cannot offer a dead option.
- **Document types are grouped by rows in `document_type_groups`**, arranged once by `DocumentType::grouped()` and offered by both the upload form and the file manager's tracking dialog. `/document-types` lists the **groups** and `/document-types/group/{group}` the types inside one, where `{group}` is an id, `other` or `all` — "Other" is a real page because deleting a group produces ungrouped types. A group has its own CRUD behind the **same** `document-types.*` permissions — one piece of office vocabulary, one grant. `group_id` is `nullOnDelete`: deleting a group rearranges the picker and must never retire a type, which then shows under "Other". A group's `code` is generated, never shown and never regenerated on rename, because the seeder matches on it.
- **A form split across tabs pairs `useUrlTab` with `useTabbedErrors`.** The server can refuse it for a field on a tab the person is not looking at; the composable moves them there and focuses it. The tab→fields map is declared, in tab order, because a hidden tab's fields may not be in the DOM at all — the Users create form and the upload policy both use it.
- **`useConfirmSubmit`'s `request()` will not open a dialog over an invalid form.** Bind it to `@submit.prevent="request"` and mark required inputs `required`; it calls the form's own `reportValidity()` first. Asking "create this?" about a form the server will refuse puts the errors *behind* a dialog the person must dismiss to read them.
- **A tracking code opens one page, and that page is not the document.** `/track` is public (`PublicTrackingController`) and `/scan` forwards a visitor to it; `/documents/view/{code}`, `/documents/track` and `documents.preview` still require `auth`. The code is *printed on the folder* and is a short, sequential daily series, so it is not a credential and buys nothing beyond what `AccessResolver` already grants a null user: a **public** document is described and previewed, a **private or confidential** one answers with its classification and nothing else — no title, no uploader, no file — and a signed-in reader the resolver grants `view` is redirected to `documents.view`. The resolver is untouched. Somebody who needs a *copy* gets a **share link**, which carries an ability, an expiry, a view cap, a recorded redemption and a revoke button; `FilePreview` reports `can_download` false for a signed-out reader, so a code is a look and a link is a copy. Cost, stated rather than hidden: the page discloses that a code is live and how it is classified, which is why the route is throttled. A lookup has **three** answers, not two: `TrackingCodeService::looksLikeCode()` (the mask lives beside the code that composes one, and both doors ask it before the database) separates "that is not a tracking code" from "no document carries that code", because the two send a person to different places. The frontend does not restate the mask — `TrackDocumentCard` checks only empty input, whitespace, length and a foreign-origin URL from a scan.
- **An item has one live share link, and its terms are edited rather than replaced.** `SharingService::createLink()` refuses a second; `updateLink()` changes the one that exists and **keeps its token**, because revoke-and-recreate silently breaks every message the old URL was pasted into. `view_count` is never reset by an edit. Linkability is re-checked on edit as well as creation.
- **A share-link visitor is asked who they are, and may decline.** `App\Services\Files\GuestIdentity` — declining mints a stable per-device handle, so the trail distinguishes two visitors without learning either name. **Nothing is recorded and no view is spent until they answer**, and `/s/{token}/file` redirects to the prompt too, or the prompt is decoration. It is **not authentication**: the name is snapshotted into `actor_name` with `actor_id` null and always suffixed "(link visitor)", and it decides nothing.
- **The share landing page previews through `FilePreview`**, with the link passed to `describe()` so abilities resolve through the token and the bytes come from the token's own stream route. It used to test `in_array($mime, INLINE_TYPES)` itself, which refused every Office document (OOXML sniffs as `application/zip`) and told the holder the *link* did not permit opening the file.
- **A share link never grants write, and a confidential item can never have one** — checked at creation *and* on every redemption, because an item can be reclassified after a link is handed out. On the share and file-stream routes **every** refusal is a 404, deliberately unlike the rest of the app: a 403 would confirm the token or identifier is real.
- **`App\Services\Access\AccessResolver` is the single place access to a file, folder or document is decided.** `DocumentController::isAuthorized()` / `::owns()` and `DocumentLogController::canSee()` all delegate to it. Those first two used to be hand-copied duplicates of each other, each carrying a comment saying the pair had to change together; one resolver is the only thing that stops that being something a future change must remember. The document clauses are reproduced in it verbatim and in order, because `tests/Feature/DocumentAuthorizationTest.php` is their contract.
- **Those callers keep returning a redirect, not a 403.** `DocumentAuthorizationTest` asserts `assertRedirect('/dashboard')` with a flash. Use `Gate`/resolver checks plus `unauthorizedRedirect()`; do not switch them to `$this->authorize()`.
- **Only the uploader may edit or delete a document** (`::owns()`). Both checks are load-bearing: without them any authenticated user could rewrite or delete any document in the office.
- **`documents` carries no state columns at all.** `status`, `ended_at`, `is_ended`, `target_division_id`, `target_section_id` and `document_logs.status` have all been dropped — the first two with the End Action, the rest as leftovers nothing read.
- **QR Trackers are PNG with the DOST-PTRI seal embedded**, built only by `App\Services\Documents\QrLabelService` (`endroid/qr-code`, GD — *not* `simple-qrcode`, whose PNG and logo paths both need the Imagick extension these servers lack). **High error correction and the 22% logo cap are load-bearing**, not styling: they are what leaves the symbol readable with a seal punched into it. PNG for the stored label and the download, SVG for rendering inline. Labels are named after the tracking code (`{code}.png`) — never the document title, which is arbitrary user input that collided and, on a public download route taking the filename, was a traversal risk. `downloadQr()` matches the requested name against a stored `qr_code_path` before touching the disk, so older `.svg` rows keep working. `QrLabelTest` decodes a generated label and asserts the tracking URL comes back; keep it, because a logo that breaks scanning fails silently.
- **A tracking code is per type, per day, sequential:** `ABBR-YYYYMMDD-NNNN`, issued only by `App\Services\TrackingCodeService::issue()`. The counter is `max(highest code on record, the document_series row's counter) + 1` under a row lock; both halves are load-bearing (import continuity, and never reissuing a deleted document's code). It is not "documents created today", which handed out duplicates as soon as two types were uploaded on one day.

- **Document types are a table, not a constant.** `document_types` is both the list the upload form offers and the map to code prefixes; `code` is immutable in practice because it is stamped into every code that type has issued. Retire a type with `is_active`. `DocumentTypeSeeder` is not sample data — nothing can be uploaded without it, which is why `Tests\TestCase` seeds it.

- **There are three audit tables and the difference is the audience.** `document_logs` is a document's travel history, shown to **everyone who can read that document**; `document_downloads` is the narrow "a copy left" register with its IP; `activity_logs` is everything that happens to a file or folder, behind `activity-trails.read`. Only `previewed` and `downloaded` cross from the third into the first — a `copied` or `extracted` row in a document's trail would disclose the file manager to every reader of the document. `App\Services\Files\FileEventRecorder` is the one place they are written together.
- **Write audit rows only through their single factory**: `DocumentLog::record()`, `DocumentDownload::register()`, `ActivityLog::record()`. A second construction site is how a table ends up with rows missing the actor's office.
- **Preview is debounced, download is not.** An iframe re-requests on every re-render, and a row per render is a forged history. Each download is a separate copy leaving the server. Both existence checks run *before* the record, so a missing file never leaves a record of a release that did not happen.
- **No audit row ever carries a live credential.** A share link's token is never recorded: it would make the audit report a way to obtain the credential.
- **Audit rows snapshot their actor; they do not join one.** `document_logs` and `document_downloads` carry `actor_name` / `user_name`, `division_name` and `section_name` beside the foreign keys, and the pages render the snapshots. Write them only through `DocumentLog::record()` and `DocumentDownload::register()`, which is the one place the shape is built. Every foreign key on an audit row is `nullOnDelete` so the row outlives what it points at — including `documents.user_id`, which used to cascade and delete a departing user's documents.

- **The header bell's vocabulary is `App\Enums\NotificationKind`.** A notification stores a `kind` slug plus a snapshot of the actor's name and face; `NotificationController::feedFor()` resolves the label, icon and colour from the enum. Read it with `tryFrom()` — rows written before the key existed have none, and fall back to a bell with no face rather than being guessed at from their sentence.
- **A tracked document's recipient list is editable on the edit form** (private and confidential; the *level* is not). `DocumentController::update()` diffs against the live list — additions through `DocumentRegistrar::tag()` plus a `ViewerAdded` row, removals through `revokeViewer()`, which is the one place the `revoked_at` stamp and its `ViewerRemoved` row are written. Notifications go out **after** the commit.
- **`document_logs.action` is an `App\Enums\DocumentAction`**, and only `DocumentAction::postable()` may be submitted by a user. The endpoint used to accept any string up to 255 characters. The line is *who observes the fact*: the system records `Uploaded`/`Viewed`/`Downloaded`/`LinkShared`/`LinkRevoked` and a client must never be able to claim one; `Received` is postable because only the person can say a document reached them.
- **There is no "Receive & download".** It fused taking a copy (observed by the server) with confirming receipt (assertable only by the person), so you could not record that a document arrived on paper without also pulling the file. `Received` is logged from the **Log action** form and Download is its own link; `documents.receiveFile` and `DocumentController::receiveFile()` are gone. The once-per-person rule moved to `DocumentLogController::store()`, beside the fact rather than beside the endpoint.
- **File responses must stay out of Inertia.** `accessFile`, `downloadQr` and `files.stream` return file responses, which an Inertia XHR visit cannot follow. Reach them with a plain `<a href>` or `window.location` — never `router.visit`.
- **Files live on the private `documents` disk and are served only by a controller.** Nothing is under `public/storage` any more: uploads used to go to the `public` disk, so every document was readable at `/storage/documents/<hash>.pdf` with no check at all. Read and write bytes through `App\Services\Files\FileStorage` and build paths only in `FilePathFactory` — never `storage_path()` interpolation, which is also what made these paths untestable under `Storage::fake()`.
- **A file URL is `/files/{ownerPublicId}/{filePublicId}`**, both 26-character opaque `public_id`s constrained in the route, so traversal is refused by the router. The owner segment is verified against the file's real owner, and every refusal is a 404 — a 403 would confirm the identifier exists. See `documentation/modules/files.md`.
- **`document_logs` and `document_downloads` are different things.** The first is the document's human-readable travel history, shown to anyone who can read the document. The second is the narrower "a copy left the server" register behind `/admin/download-logs`, and it carries the IP a copy went to, which has no business on a document page. A download writes both, and the second points at the first through `document_log_id`.

- **Divisions and sections carry a `code` as well as a `name`**, and a section's code and name are unique *within* its division — two divisions may each run a "Records" section, but one may not run two. **There is no separate employee directory any more** — `employees` was merged into `users` and dropped, so one person is one row and one sign-in. A person's name is stored as `first_name` + `last_name`, and `name` is a **derived** column the model's `saving` hook assembles from them: never write it directly, because the next save overwrites it. It stays a real column because audit snapshots and `files.owner_name` copy it and a query cannot call an accessor.
- **Flash keys are `success` and `error`, nothing else — and the two are answered differently.** Both are shared by `HandleInertiaRequests`. A `success` becomes a `ToastStack` toast; an `error` opens `AdminShell`'s `FeedbackModal`. That asymmetry is the point: a success is the outcome the person just asked for, so blocking the screen to announce it interrupts the work it completed, while a refusal the reader scrolls past is one they will act as though never happened. Controllers that flashed `status` were normalised; **do not reintroduce a third key** — a per-case modal title is not worth it, because the specifics belong in the message the controller already writes.
- **Tests run against MySQL, not SQLite** (`dms_test`, see `phpunit.xml`): the deployment target ships `pdo_mysql` but not `pdo_sqlite`.
- **`tests/Feature/Acceptance/` is the office's checklist, not a second copy of the suite.** Each file covers a numbered acceptance item end to end through the screens — a mixed batch of uploads, the three visibility levels against four audiences, the upload rules an administrator actually sets, one role swept against every module, the file-manager menu and the trash, audit coverage over a whole session, and what survives a deletion. The per-clause tests beside it stay the contract for the rules themselves; these assert that the clauses add up to the behaviour somebody asked for. `actingAs()` persists for the rest of a test, so a "visitor with no account" assertion must sign out first — otherwise it silently asserts something about the uploader.
- `routes/auth.php` is registered by `bootstrap/app.php`'s `then:` callback. It went unloaded for the whole of the app's first life, which is why password reset never worked. Do not redeclare login/logout in `web.php` — they were duplicated in both files and whichever loaded last silently won.
- **There is no self-registration.** `RegisteredUserController`, `pages/auth/register.js` and both `/register` routes were removed: the route created a working account with no approval and no check that the employee ID was real. Accounts come from the Users screen (`users.write`), which is also where the role is chosen. Do not reinstate it behind an approval flag — a pending account is a second kind of account every sign-in and listing would have to know about.

- **Realtime is Reverb, and it fails soft.** `resources/js/echo.js` builds no connection when `VITE_REVERB_APP_KEY` is absent, and `listen()` returns a no-op unsubscribe — so a deployment without a supervised `reverb:start` still works from its Inertia props. Its `connection` ref (`off` / `live` / `down`, from Pusher's `state_change`) colours the DocTrack wordmark in `AppNavbar`: green connected, red not, white unconfigured. Read `connection`, never `realtime()`, for anything that claims to be a status — the latter answers "was an Echo built". **`REVERB_APP_SECRET` must never gain a `VITE_` twin**: anything prefixed that way is compiled into the bundle.
- **A trail broadcasts a signal, not the row.** `DocumentTrailUpdated` / `ActivityTrailUpdated` carry an id and a timestamp; the client reloads the prop through the controller. Three reasons: the lists are **paginated** (splicing a pushed row makes totals disagree with contents), a refetch is re-authorized and re-serialized by the one path that already gets it right, and **no audit row ever carries a live credential** — a signal cannot violate that, a payload must be re-checked every time it changes. Dispatched from `DocumentLog::record()` and `ActivityLog::record()`, so no writer can add a row without the page hearing about it. `ShouldBroadcastNow`, because queued they would never arrive without a supervised worker.
- **`routes/channels.php` is the entire gate.** `/broadcasting/auth` carries `web` and no `permission:` middleware, so a channel callback that forgets something is open. `documents.{document}` asks `AccessResolver` — the same rule that decides whether the trail page opens, because a log listing who received a confidential case file is a disclosure of its own. `ChannelAuthorizationTest` holds a **differential** test asserting the channel answers exactly what the resolver answers. Use `find()`, never `findOrFail()`: an exception in an auth callback is a 500, not a refusal.
- **In a channel test, swap the broadcaster *and* re-register.** `phpunit.xml` sets `BROADCAST_CONNECTION=null` so the suite needs no websocket server — but the null driver answers 200 to everything and never runs the callbacks, so a refusal test against it is green whatever the callbacks say. Channels register on the **resolved** driver, so after `config(['broadcasting.default' => 'reverb'])` you must `Broadcast::forgetDrivers()` and re-require the channels file.
- **A document can be asked for.** `access-requests` has `read` and `create` and deliberately **no decide permission**: who may answer is a per-record question (the request is addressed to the uploader), and a module checkbox would create requests nobody holding it could answer. Granting is a `document_recipients` row through `DocumentRegistrar::tag()` — the list `AccessResolver` already reads — so the feature adds **no new way into a document** and the resolver is untouched. The refusal itself is unchanged; `unauthorizedRedirect()` just carries the code in its own session key, never a third flash key and never the title.
- **A removed viewer is stamped, not deleted, and gets a different refusal.** `document_recipients.revoked_at` keeps the row, so "you were removed as a viewer" can be told apart from "you were never tagged" — the second invites the reader to ask, the first answers a question already decided about them. `Document::recipients()` and `User::receivedDocuments()` are therefore the **live** list (`wherePivotNull('revoked_at')`); writes go through `allRecipients()`, because the unique pair means re-tagging has to revive the row rather than insert one. A revoked share *link* still answers 404 like an unknown token: there is no identity for a message to be about.
- **A tracked upload has one implementation.** `App\Services\Documents\DocumentRegistrar` issues the code, writes the QR Tracker, creates the document, opens the trail and tags recipients; `DocumentController::store()` and `FileActionController::upload()` both call it. Tracking from My Files is **opt-in and takes exactly one file** (a code names one document), and the file stays in the folder the person was browsing. The register's form has a destination picker (`FolderPickerModal`, `folder` = a folder public id) defaulting to the uploader's root; an unwritable destination is refused, not swapped. Nothing creates a `Tracked Documents {year}` folder any more — only `files:purge --orphans` still names it, to collect historical wreckage.

## Keeping docs current (living-docs rule)

When a module's controller, model or page changes materially, or a module is added, update its context doc in the same change:

- Context doc: `documentation/modules/<module>.md`
- Design-system changes (a new shared component, a token, a page recipe): `documentation/design-system.md`
- Cross-module architecture and "why": `CLAUDE.md`

`documentation/project-stack.md` owns the stack and directory overview; `documentation/migration-notes.md` is a historical record of the Blade-to-Inertia conversion and should not be rewritten, only appended to.
